# Task 02：智能体发展史

学习资料：[Hello-Agents 第二章](https://github.com/datawhalechina/hello-agents/tree/main/docs/chapter2)。

## 一、全章脉络

本章围绕“如何让机器获得智能”展开：早期研究者尝试把知识写成符号和规则；随后，研究者探索简单组件协作、神经网络从数据中学习，以及强化学习从环境反馈中改进决策；大规模预训练又让语言模型获得处理多类任务的能力。现代智能体把语言模型与工具、记忆和执行程序等组合起来。

这些思路并不是前一种被后一种完全取代，而是长期并存、相互影响，也会组合使用。

## 二、符号主义：把知识和规则明确写出来

符号主义使用人类可描述的符号表示知识，再用逻辑规则操作这些符号。例如：

> 如果天空下雨，而且目的地是户外景点，那么建议带伞。

**物理符号系统假说**认为物理符号系统具有产生通用智能行为所需的充分手段，并提出这类系统对于通用智能是必要的。这是一种重要的研究假说，不应把它当作已经被完全证明的结论。

**专家系统**通常包含知识库和推理机。知识库存放领域规则；推理机根据事实匹配规则并推导结论。正向推理从已有事实寻找结论，反向推理从假设或目标倒推所需证据。MYCIN 是医疗领域专家系统的代表，使用规则辅助分析感染及治疗方案。

**SHRDLU** 在简化的积木世界中理解指令、规划动作并维护世界状态。例如，目标积木被挡住时，它可以先移开障碍物。它展示了语言、规划和行动的结合，但其能力受到限定环境的约束。

这一方法的优势是规则清晰、推理路径相对容易追踪；困难是知识需要获取和维护，现实中的常识与例外很难穷举，遇到规则以外的情况可能表现脆弱。

## 三、ELIZA：规则聊天机器人的启发

ELIZA 的典型做法是识别输入中的关键词或句式，匹配预先设计的规则，再用模板重组回复。例如：

```text
用户：我觉得学习很困难。
规则：匹配“我觉得……”
回复：你为什么觉得学习很困难？
```

这个例子说明：看似自然的对话可以由简单的匹配与替换产生，但规则有限时，很难覆盖多样的表达和复杂上下文。教材 2.2 提供了简化实现；本次打卡要求是笔记，这里记录原理，没有声称运行过该代码。

## 四、心智社会：复杂行为可以来自协作

明斯基的“心智社会”把复杂智能设想为许多较简单过程相互协作的结果。以搭积木为例，识别积木、抓取和放置可以由不同功能负责，协调起来完成搭塔。

它对多智能体系统的启发是：可以按职责划分任务，让不同组件协作。但分工也带来通信、协调和错误传递问题；一个必要的组件失败时，整个任务可能受阻。这种思想与现代多智能体设计有联系，但不能认为二者完全等同。

## 五、从规则到学习

### 1. 联结主义与神经网络

神经网络通过数据调整参数，学习输入与输出之间的关系。与逐条手写规则相比，它更适合从大量样本中提取复杂模式，例如图像或语言中的规律，但结果可能不易解释，也会受训练数据影响。

### 2. 强化学习

强化学习中，智能体观察环境状态，依据策略选择行动；环境返回新的状态和奖励；智能体利用反馈改进策略。它关注长期累计回报，而不只是眼前的一次奖励。以下棋为例，一步暂时吃亏的棋，有时可能有利于最终获胜。

### 3. 预训练与微调

预训练使用大量数据先学习通用模式；微调再用特定任务或偏好数据调整模型。语言模型能借助预训练知识应对多种任务，减少对逐条人工编写知识的依赖，但并没有彻底解决事实错误、过时或偏见等问题。

## 六、现代大语言模型智能体

一个常见系统由大模型、提示与规划、工具、记忆和执行程序等组成。基本过程是：接收任务 → 模型决定下一步 → 程序调用工具 → 读取工具结果 → 继续行动或给出答案。并非每个智能体都具备独立的所有模块。

和第一章的旅行助手联系起来：大模型决定先查天气；天气 API 返回观察结果；模型再选择搜索景点；最后整合结果。模型负责生成决策内容，工具的实际执行由程序完成。工具返回结果和最终建议仍需核查。

## 七、对比与收获

| 思路 | 能力主要从哪里来 | 适合关注的问题 | 常见局限 |
| --- | --- | --- | --- |
| 符号规则 | 人编写的知识和逻辑 | 规则明确、需要追踪依据的任务 | 规则维护困难，覆盖例外有限 |
| 神经网络 | 从训练数据中学习参数 | 识别复杂模式、处理语言和图像 | 依赖数据，结果可能不透明 |
| 强化学习 | 与环境交互及奖励反馈 | 多步决策与长期目标 | 交互成本、奖励设计与安全问题 |
| 大模型智能体 | 预训练模型结合工具和程序 | 理解自然语言、多步骤调用工具 | 可能出错、工具失败或产生幻觉 |

我的理解是：智能体的进步既与知识如何获得有关，也与怎样行动、接收反馈和协作有关。实际应用中，可以把明确规则用于边界约束，把模型用于理解和灵活处理，同时保留验证和人工检查。
