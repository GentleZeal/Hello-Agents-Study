# Task 03：大语言模型基础

学习材料：[Hello-Agents 第三章](https://github.com/datawhalechina/hello-agents/tree/main/docs/chapter3)。

## 语言模型与 Transformer

语言模型根据已有上下文预测接下来的内容。早期 N-gram 依赖有限长度的前文统计，RNN 按顺序处理序列；Transformer 利用注意力机制在处理序列时关注不同位置之间的关系。注意力机制帮助模型结合上下文，但它不保证理解或回答一定正确。

第三章还介绍了 Decoder-only 架构：模型结合已有文本逐步预测后续 token。实际训练和推理过程包含更多技术细节，不能简单等同于查找一句固定答案。

## Token 与提示

文本输入需要经过分词器处理为 token 和对应的数字编号。Token 不一定等于一个字或一个单词；中英文、标点和不同分词器的切分都可能不同。模型生成编号后，再由分词器转换成文本。

提示词用于表达目标、上下文、约束和期望格式。清晰地说明需求、提供必要背景及示例，通常更容易得到有用的回答，但提示再好也不能保证结果正确。

## 本地模型和 API

API 调用是在网络上向服务商发送请求并接收回答；本地推理则把模型文件下载到电脑上，由本机执行计算。下载本地模型需要网络，运行时是否可以离线取决于具体软件和配置。本地部署消耗磁盘、内存和计算资源；模型越大通常越需要更强硬件。量化通过降低参数表示精度来减少占用，也可能影响输出质量。

教材 3.2.3 使用 Transformers 加载 Qwen1.5-0.5B-Chat；习题也推荐 Qwen3-0.6B。本次使用 Ollama 运行本地 Qwen3 0.6B，工具与教材示例不同。

实践时运行 `ollama run qwen3:0.6b`，向模型提问“请用两句话介绍什么是大语言模型”，终端出现思考过程和最终回答，表明本次对话生成成功。[查看运行截图](运行截图.png)，其中本机用户名已遮挡。

## 局限与思考

大语言模型可能产生幻觉：回答流畅却不符合事实。知识也可能过时，或受到训练数据偏差影响。对重要信息应检查来源，必要时结合检索、工具和人工核实。模型规模、数据和计算资源影响能力，但扩大规模不意味着每项任务都会可靠。

联系前面的旅行助手：模型生成下一步行动文本，程序执行天气或搜索工具，再把结果反馈给模型；单独运行本地语言模型并不自动具备这些工具能力。
