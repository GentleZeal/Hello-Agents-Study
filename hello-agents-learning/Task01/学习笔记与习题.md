## 学习笔记

智能体围绕目标与环境交互：获取信息，根据已有信息决定下一步行动，执行行动并接收反馈，再决定是否继续。大语言模型可以帮助理解任务和选择行动；程序负责解析模型输出、调用工具并反馈结果。模型和整个智能体系统并不完全相同。

旅行助手的循环：先调用天气工具，取得天气观察；再根据天气调用景点搜索工具；最后整理信息，以 Finish 输出答案。截图中天气与搜索都返回了结果，程序正常结束。运行成功不代表推荐内容一定准确，还需要核实。

PEAS 用四个角度描述任务：性能度量（如何判断好坏）、环境（在哪里工作）、执行器（能做什么）和传感器（能接收什么信息）。Workflow 的流程主要由人预先安排；Agent 可以根据目标和反馈选择下一步。两者可以结合使用。

## 习题

### 1. 判断主体是否为智能体

- A：仅知道超级计算机有很高算力，不能认定它是智能体。它是计算设备；具体运行在其上的系统若具有目标、感知与行动机制，则可能是智能体。
- B：自动驾驶系统感知道路、根据目标控制车辆，是智能体。遇到障碍时的紧急避障体现反应式决策；完整自动驾驶系统也需要路线规划，可视为混合式。
- C：AlphaGo 根据棋盘状态选择落子并追求胜利，是基于目标、具备规划能力的智能体；它的策略也通过训练获得，具有学习型系统的特点。
- D：如果客服系统能查询订单、根据结果选择后续动作并提供解决方案，就可以视为大模型驱动的智能体。仅生成一段固定回答的聊天功能，是否构成完整智能体则取决于其实际能力。

### 2. 智能健身教练的 PEAS

| 维度 | 内容 |
| --- | --- |
| P 性能度量 | 训练目标达成情况、动作规范程度、用户安全、计划执行情况和用户满意度 |
| E 环境 | 用户、健身场地、器械、可穿戴设备及运动过程 |
| A 执行器 | 语音指导、展示动作提示、调整计划、发送提醒和建议 |
| S 传感器 | 心率与运动传感器、用户输入、训练记录；若有授权，还可使用摄像头识别动作 |

环境是部分可观察的：设备不能完整知道用户身体状况；也是动态的：运动状态持续变化；具有不确定性：同一训练的效果因人而异；还是序贯的：当前训练会影响后续疲劳和安排。饮食或健康建议需要结合个人情况，由专业人士判断。

### 3. Workflow 与 Agent 的售后方案

固定流程规则清楚、便于审计，处理标准案例稳定，但遇到规则未覆盖的复杂情况不够灵活。Agent 能综合不同信息处理复杂情形，但判断可能出错，解释和一致性需要验证，成本也可能更高。

标准、低风险且规则明确的申请适合 Workflow；需要理解复杂上下文的申请适合由 Agent 辅助。较稳妥的方案 C 是：用固定规则处理明确情形，复杂案例由 Agent 整理证据并提出建议，涉及较高金额或争议时交给人工审核；记录决策依据并保护用户数据。

### 4. 改进旅行助手的设计

- 记忆：保存经用户同意的偏好和预算，在下一轮提示中提供相关内容，并允许修改或删除。
- 售罄备选：增加门票查询工具，把售罄结果作为 Observation；模型据此查询其他符合条件的景点，再确认票务信息。
- 连续拒绝：记录被拒绝次数与原因；达到三次时先总结偏好不匹配之处，询问用户更看重什么，再调整推荐策略。设置循环次数上限，避免反复尝试。

### 5. 快速反应与审慎推理的协同

以智能健身教练为例：快速环节负责识别心率超过预设阈值并提醒停止；审慎环节结合近期训练记录、目标和疲劳情况，调整下一周训练计划。快速环节先处理紧急事件，审慎环节再综合信息分析；两者共享经过核实的数据，并由用户或专业人士决定重要调整。这里的系统 1 和系统 2 是帮助理解的类比，不等同于对模型内部过程的证明。

### 6. 局限、循环限制与评估

幻觉可能来自模型生成了看似合理但缺乏依据的内容，也可能来自过时或错误的信息、工具结果错误及误解上下文。可以通过可靠工具检索、核对来源和对关键结论进行验证来降低风险，但不能保证彻底消除。

不限制循环次数时，智能体可能反复调用工具、无法结束，并持续消耗时间和调用额度。设置上限并在失败时提示用户有助于控制风险。

评估不应只看最终答案准确率，还可以看任务完成率、工具调用是否正确、信息是否有依据、耗时和成本、面对失败时的恢复能力，以及隐私与安全表现。应结合具体任务设计测试。
